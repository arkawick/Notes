# Public Python dependencies for running CMWEB locally on Linux.
#
# This file is substituted for cmweb-project/etc/requirements-<20|22>.txt, so
# that the upstream `make install` target works unmodified. setup.sh symlinks
# site/etc/requirements-20.txt and site/etc/requirements-22.txt at this file.
#
# Differences from the real requirements-22.txt, and why:
#
#   * Every Sony-internal package is absent. c2dclient, cmwebclient,
#     commit-message, commit-message-checker, generic-pages, jenkinsclient,
#     jiraapi, mplusclient, nvlayer, nvmerge, objectgenerator, repo-manifest,
#     somc-decorators, somc-django-inlines, somc-dmsclient, somcutil and
#     vendorrelease are published only on Sony's internal index. The shims in
#     stubs/ stand in for them.
#
#   * django-rest-swagger is absent. 2.1.1 is incompatible with DRF 3.15 and
#     is unmaintained; stubs/rest_framework_swagger serves a notice page.
#
#   * python-ldap / django-auth-ldap are absent by default. Local development
#     uses Django's own ModelBackend (see README "Authentication"), and the
#     real packages need libldap2-dev + libsasl2-dev and a reachable LDAP
#     server to be useful. Uncomment them below if you have both.
#
#   * boto3, celery[sqs], flower, psycopg2-binary, pyodbc, pygraphviz,
#     pymemcache and pysolr are absent: SQS, PostgreSQL, ODBC, graphviz,
#     memcached and Solr are not used by a local SQLite instance. The default
#     CACHES backend in settings.py is LocMemCache.
#
#   * Versions are floated forward where the pinned version predates
#     Python 3.12. Where a version is shared with local-cmweb/requirements.txt
#     it is the version that setup has been observed to work with.
